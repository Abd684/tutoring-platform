# لقاء — تسليم تعديلات مسار الطالب إلى فريق Flutter

تاريخ الإتاحة: 17 أكتوبر 2026 بتوقيت دمشق. حالة التنفيذ: مطبّق على المشروع المحلي وعلى السيرفر. يغطي طلب `LIQAA_BACKEND_STUDENT_ISSUES_2026-10-16.md` بأقسامه الستة.

## 1. العنوان والمصادقة وقواعد الاستجابة

عنوان الـAPI الذي تم التحقق منه:

```text
https://mandobe.net/liqaa/api/v1
```

كل المسارات أدناه نسبية إلى هذا العنوان. لا تكرر `/api/v1` عند تركيب الرابط. احتفظ بإعداد هذا العنوان في التطبيق إذا كان مستخدماً حالياً؛ لا تحول إلى تطبيق آخر على نفس الدومين.

الطلبات المحمية تحتاج توكن تسجيل دخول الطالب الموجود، المرتبط بجهازه الحالي وجلسة جهاز فعالة. لا تستخدم توكن مدرس أو توكن Sanctum عام لا يرتبط بجلسة جهاز.

```http
Accept: application/json
Authorization: Bearer <student_access_token>
Content-Type: application/json
```

النجاح في قوائم القراءة: `status: true` و`data` مصفوفة و`meta` للتصفح. لا تعتمد على وجود `message` في النجاح. الأخطاء قد تعيد `message` و`errors` دون `status`؛ افحص HTTP أولاً. القائمة الفارغة أو صفحة خارج عدد الصفحات تعيد 200 مع `data: []`؛ لا تعرضها كتعطل بالخدمة. `avatar_url: null` يعني استخدام الصورة البديلة في Flutter.

للمسارات الجديدة المرقمة: `page` عدد صحيح يبدأ من 1، و`per_page` من 1 إلى 100. الافتراضي 20، باستثناء التقويم 50. استخدم `meta.current_page`, `last_page`, `total`, `per_page`. لا تحصر نتائج البحث في الصفحة الأولى أو قسم الأبرز.

## 3. شاشة الأساتذة والبحث والفلاتر

استخدم `/teachers` أو `/teachers/directory` للقائمة والبحث، و`/teachers/featured` لقسم الأبرز مستقلاً.

| Query | السلوك |
|---|---|
| `search` | بحث جزئي باسم المدرس، حتى 100 حرف، والمسافات الطرفية تُهمل |
| `specialization` | بحث جزئي في التخصص حتى 100 حرف |
| `region_id` | مطابق لمنطقة حساب المدرس `users.region_id`، عدد صحيح موجب |
| `subject_id` | المدرس لديه عرض فعال لهذه المادة، والمادة فعالة، عدد صحيح موجب |
| `page`, `per_page` | التصفح المذكور أعلاه |
| `grade` | غير مدعوم؛ القيمة غير الفارغة تعيد 422 صراحة |

الفلاتر مجتمعة بعلاقة AND. `%` و`_` المدخلتان في البحث تُعاملان كحروف، وليس كتعليمات SQL wildcard. لا نتائج مطابقة: 200 وقائمة فارغة. ترتيب الدليل ثابت حسب معرف المدرس تصاعدياً.

الدليل يشمل كل مدرس فعال بحساب فعال، حتى دون اشتراكات طلاب. لا توجد تصفية إجبارية بحسب صف الطالب أو منطقته، ولا اعتماد على وجود اشتراك. منطقة الطالب يمكن أن تُستخدم كاختيار أولي في الواجهة فقط إذا عرضتم للمستخدم ذلك وأتحتم تغييرها؛ ليست قيد صلاحية.

**قرار الصف:** قاعدة البيانات الحالية لا تربط عروض المواد بصفوف تدريس. لا ترسلوا `student.grade` إلى هذه القائمة، ولا تضيفوا فلتر صف يوهم بوجود مطابقة. يتطلب تفعيل هذا الفلتر لاحقاً نموذج بيانات معتمداً؛ لم نختلق هذه العلاقة. منطقة المدرس ليست بالضرورة منطقة الطالب.

بطاقة المدرس تعيد حصراً `id, name, specialization, avatar_url, status, region_id`. لا يوجد تقييم نجوم في هذا العقد. الأبرز يعيد `active_students_count` وترتيبه تنازلي بحسب عدد الطلاب الفعالين المميزين، وليس قيمة تقييم. لا تضعوا نجوم وهمية.

مثال حقيقي تم جلبه عبر HTTPS بعد النشر: `GET /teachers?search=أحمد%20الشامي`، HTTP 200:

```json
{
  "status": true,
  "data": [
    {
      "id": 1,
      "name": "أحمد الشامي",
      "specialization": "الرياضيات",
      "avatar_url": null,
      "status": "active",
      "region_id": 1
    }
  ],
  "meta": {
    "current_page": 1,
    "per_page": 20,
    "total": 1,
    "last_page": 1
  }
}
```

## 4. تقويم المدرس والحجز

```http
GET /teachers/1/calendar?from=2026-10-18T00%3A00%3A00%2B03%3A00&to=2026-10-19T00%3A00%3A00%2B03%3A00&timezone=Asia%2FDamascus&page=1&per_page=50
```

استخدموا Uri/queryParameters لترميز `+` والتواريخ؛ لا تركبوا رابطاً يعتبر `+03:00` مسافة.

| Query | العقد |
|---|---|
| `from` | بداية مشمولة، تاريخ ISO 8601؛ الافتراضي بداية اليوم في timezone العرض |
| `to` | نهاية غير مشمولة، بعد from وبحد أقصى 31 يوماً؛ الافتراضي from + 7 أيام |
| `timezone` | اسم IANA مثل `Asia/Damascus`، الافتراضي UTC |
| `page`, `per_page` | ترقيم **الفترات**، وليس الأيام أو الجلسات؛ الافتراضي 50 |

التاريخ ذو offset أو Z يحتفظ بمعناه الزمني. التاريخ دون offset يفسر في timezone الطلب. العرض يرجع ISO 8601 مع offset منطقة العرض؛ قد تبقى `meta.from/to` بـUTC. توافر المدرس يفسر في منطقته المسجلة، ولا تستبدلوها يدوياً بمنطقة الجهاز. اجلبوا كل الصفحات قبل الحكم على اليوم كله.

التقويم يقسم كامل الفترة إلى مقاطع، وقد تظهر مقاطع إضافية عند منتصف الليل أو بداية/نهاية اشتراك أو حجز. لا تفترضوا أن كل مقطع يمثل جلسة محفوظة، أو مدة الحصة الثابتة. يعرض أوقات الماضي كغير متاحة أيضاً. الزمن القابل للحجز يبدأ من الدقيقة المستقبلية التالية عندما يقطع الطلب اللحظة الحالية.

| `status` | `reason` | ماذا يعرض Flutter؟ |
|---|---|---|
| available | available | زر حجز، فقط إذا `bookable=true` |
| booked | booked | المدرس مشغول، لا زر حجز ولا هوية صاحب الموعد |
| unavailable | closed | توافر مسجل بحالة disabled، لا زر |
| unavailable | outside_schedule | لا توافر يغطي هذا الجزء |
| unavailable | not_eligible | يوجد توافر لكن اشتراك الطالب لا يغطي الفترة |
| unavailable | student_conflict | للطالب جلسة متعارضة |
| unavailable | past | الوقت مضى أو ليس مستقبلياً قابلاً للحجز |

الأولوية عند التداخل: booked، ثم closed/outside_schedule، ثم past، ثم not_eligible، ثم student_conflict، ثم available. `session_type` قد يكون GROUP أو INDIVIDUAL في الأوقات المشغولة، ولا يعني السماح بانضمام جماعي عبر زر الحجز الفردي. `session_status` حالة الجلسة المشغولة أو null.

`meta.has_schedule` يعني وجود توافر مسجل متداخل مع الفترة، بما فيه disabled. `meta.has_eligible_enrollment_in_period` يعني وجود اشتراك صالح زمنياً في جزء من الفترة، ولا يثبت وحده وجود موعد قابل للحجز. اعتمدوا على `bookable` في كل مقطع.

**عقد الحجز المعتمد:** لا ننشئ جلسة لكل ساعة توافر مسبقاً. الجلسة الفعلية تُنشأ عند الحجز. لذلك `session_id` في التقويم دائماً null. استخدموا `availability_id` ومعرفاً من `eligible_enrollment_ids` العائدة للطالب الحالي، وهي لا تظهر إلا في المقطع القابل للحجز.

```http
POST /teacher-availabilities/{availability_id}/book
```

```json
{
  "enrollment_id": 42,
  "starts_at": "2026-10-19T10:00:00Z",
  "ends_at": "2026-10-19T11:00:00Z"
}
```

الأرقام والتواريخ في هذا الطلب توضيحية مأخوذة من اختبار مؤقت، وليست قيماً ثابتة. اختاروا جزءاً مستقبلياً داخل المقطع، وقد يغطي المقطع ساعتين بينما يحجز الطالب ساعة فقط. الاشتراك يجب أن يخص الطالب والمدرس ويكون فعالاً وبدأ مفعوله ويغطي نهاية الجلسة. الحجز فردي بسعة 1، مع فحص التعارض للمدرس والطالب لحظة الحفظ.

النجاح 201: الجلسة الجديدة في `data`؛ خزّنوا `data.id` كـsession_id. ألغوا عبر DELETE أعلاه، وأعيدوا تحميل التقويم والحجوزات بعد الحجز/الإلغاء. 409 عند تعارض ظهر منذ جلب التقويم: حدّثوا البيانات وأبلغوا المستخدم أن الموعد لم يعد متاحاً. 422 عند فترة/اشتراك غير صالح، و403 إذا الاشتراك ليس للطالب. الإلغاء يحتفظ ببيانات الاشتراك في الجلسة الملغاة.

**لا تستخدموا `POST /sessions/{id}/book` للحجوزات الجديدة**؛ المسار القديم يرفض بعقد 409. `/available-sessions` مسار قديم مبني على جلسات محفوظة وليس مصدراً للتقويم. البديل المؤهل فقط `/available-slots` يعيد مصفوفة فترات دون pagination، بفترة افتراضية 7 أيام وحد أقصى 31؛ لا يبين سبب غياب الفترات. استخدموا `/calendar` للشاشة المطلوبة. `/student/bookings` يبقى مصدر حجوزات الطالب، ويدعم `scope=upcoming|history|all`.

## 5. اختبارات الدروس ومعرفاتها

`GET /lessons/{lesson_id}/contents` يعيد لكل محتوى منشور `quizzes_count` مساوية لعدد الاختبارات المنشورة في `quizzes`. الاختبارات draft/archived لا تدخل العدد ولا المصفوفة. البيانات العامة لا تعيد الأسئلة أو الإجابات الصحيحة.

الدرس المطلوب فُحص على السيرفر عبر HTTPS: «التشبيه وأركانه»، `lesson_id=15`، والمحتوى «اختبار تدريبي: التشبيه وأركانه» `content_id=15` مرتبط بـ`quiz_id=15` منشور. تساوي الأرقام هنا مصادفة؛ ممنوع اشتقاق أحدها من الآخر أو تثبيت 15 في التطبيق.

الاستجابة الحقيقية لـ`GET /lessons/15/contents`، HTTP 200:

```json
{
  "status": true,
  "message": "Lesson contents retrieved successfully.",
  "data": [
    {
      "id": 15,
      "lesson_id": 15,
      "type": "quiz",
      "title": "اختبار تدريبي: التشبيه وأركانه",
      "description": "اختبار قصير لمراجعة أساسيات اللغة العربية بعد دراسة التشبيه وأركانه.",
      "price": "0.00",
      "order_no": 1,
      "status": "published",
      "published_at": "2026-10-01T10:05:47.000000Z",
      "learning_objectives": null,
      "assets_count": 0,
      "quizzes_count": 1,
      "quizzes": [
        {
          "id": 15,
          "content_id": 15,
          "status": "published",
          "attempts_allowed": 3,
          "duration_minutes": 15
        }
      ],
      "duration_seconds": null
    }
  ]
}
```

تسلسل Flutter:

1. اقرأ المحتويات باستخدام lesson_id.
2. استخرج `content.quizzes[].id` كـquiz_id. إذا أكثر من اختبار اعرض اختياراً بينها.
3. إذا المصفوفة غير موجودة في cache قديم، اجلب `GET /contents/{content_id}/quizzes` بتوكن الطالب؛ يحتاج وصولاً فعلياً للمحتوى. لا تخمن المعرف.
4. إذا `quizzes=[]` أو count=0، اعرض «لا يوجد اختبار منشور لهذا المحتوى». هذا ليس خللاً في المعرف.
5. افتح `GET /quizzes/{quiz_id}/data`؛ هذا المسار يطبق سياسة المحتوى ولا يفتح الاختبار لمجرد ظهور البطاقة العامة.
6. بدء المحاولة: `POST /quizzes/{quiz_id}/attempts`؛ النجاح 201 يعيد `data.attempt_id`. حفظ إجابة: `POST /quiz-attempts/{attempt_id}/answers`. تسليم: `POST /quiz-attempts/{attempt_id}/submit`. هذه مسارات سابقة بقيت فعالة، ولا تستبدلوا attempt_id بـquiz_id.

المسار الاحتياطي يعيد 200 `data: []` إن كان المحتوى متاحاً ولا اختبار منشور له؛ 404 إن لم يُسمح للطالب بالمحتوى أو لم يوجد. انتهاء/تعليق الاشتراك أو نشر المسودة لا يعطي وصولاً. اشتراك مادة كاملة يفتح محتوياتها المنشورة، الوحدة تفتح وحدتها، والمحتوى يفتح نفسه؛ حالات النشر وحسابات الأطراف تخضع للتحقق المركزي.

## 6. صفحة «اختباراتي»

```http
GET /student/my-quizzes?scope=all&page=1&per_page=20
GET /student/my-quizzes/{quiz_id}/attempts?page=1&per_page=20
```

القائمتان تعتمدـان الطالب الموجود بالتوكن. لا ترسلوا student_id، ولا تستخدموا CRUD المحاولات الإداري.

| Query للقائمة الرئيسية | السلوك |
|---|---|
| `scope=all` | الافتراضي: المتاح حالياً + أي اختبار له محاولات لهذا الطالب |
| `scope=available` | اختبارات منشورة ومحتواها متاح حالياً للطالب |
| `scope=history` | اختبارات حاولها الطالب، حتى لو بقيت متاحة؛ يحتفظ بالتاريخ بعد الانتهاء/الأرشفة |
| `status=not_started` | لا محاولات للطالب لهذا الاختبار |
| `status=in_progress|submitted|graded` | توجد محاولة للطالب بهذه الحالة |
| `status=pending_grading` | توجد محاولة submitted بدرجة null أو إجابات ما تزال معلقة/غير مصححة |
| `page`, `per_page` | الافتراضي 20، الحد 100 |

`status` يفحص وجود **أي محاولة** بهذه الحالة؛ ليس بالضرورة حالة أحدث محاولة. كل اختبار يظهر مرة واحدة وترتيب المعرف تنازلي. `history` هنا «له محاولات» وليس «غير متاح فقط». تفاصيل المحاولات كلها من المسار الثاني بترتيب الأحدث أولاً.

الحقول تشمل `quiz_id, quiz_title, quiz_status, content_id, lesson_id, teacher_subject_id, subject_name, teacher`، ثم حدود وعدد المحاولات، و`active_attempt`, `latest_attempt`, `can_access`, `can_start`, `can_resume`, `attempts_endpoint`. `quiz_title` مأخوذ من عنوان المحتوى؛ المعلم يعيد id/name/avatar_url فقط.

`attempts_used` يحسب محاولات الطالب نفسه بكل حالاتها، و`attempts_remaining` لا يقل عن صفر. `active_attempt` أحدث محاولة in_progress، و`latest_attempt` أحدث محاولة إجمالاً، وقد يكونان مختلفين. `time_expired=true` يعني انتهاء مدة المحاولة؛ لا تعرضوا زر الاستكمال. `can_resume` يحتاج وصولاً حالياً ومحاولة غير منتهية. عند وجود محاولة قابلة للاستكمال اعرضوا زر الاستكمال أولاً؛ `can_start` يعكس السماح الحالي وحدّ المحاولات ولا يعني وجوب بدء محاولة إضافية.

`score=null` مع `grading_pending=true`: «بانتظار التصحيح»، وليس صفراً. null في محاولة جارية لا يعني انتظار التصحيح. `score=0` مع pending=false درجة صفر صحيحة. لا تفترضوا أن الدرجة نسبة مئوية؛ إنها مجموع نقاط التصحيح الحالي. لا يتيح هذا المسار تعديل أي درجة أو قراءة أسئلة/إجابات تاريخية بعد انتهاء الوصول. التاريخ يبقى مرئياً لكن `can_access/can_start/can_resume` تكون false عند فقد الأهلية.

## 7. صفحة «مجموعاتي» وأعضاؤها

```http
GET /student/groups?scope=active&page=1&per_page=20
GET /student/groups/{group_id}/members?page=1&per_page=20
```

| scope | السلوك |
|---|---|
| active | الافتراضي: مجموعات active/forming بعضوية فعالة واشتراك مادة كاملة مطابق وسارٍ وحسابات ومادة ومدرس فعالين |
| history | مجموعات مرتبطة بالطالب لكنها لا تستوفي العرض الفعال الآن، ومنها المغلقة والعضوية المنتهية/المغادرة |
| all | جميع المجموعات المرتبطة بسجلات عضوية للطالب الحالي |

لا فلتر student_id. لا يمكن تغيير معرف بالطلب لجلب مجموعات طالب آخر. ترتيب المجموعات معرف تنازلي، والأعضاء معرف الطالب تصاعدي.

العنصر يعيد معلومات المجموعة والمدرس والمادة، والسعة، و`active_members_count` بعدد الطلاب المميزين ذوي العضوية والاشتراك الساريين، و`remaining_seats=max(0,capacity-count)`. تكرار اشتراك نفس الطالب لا يضاعف عدده. عدد المقاعد ليس وعداً بإمكانية الانضمام لحظة لاحقة.

`membership_record_status` الحالة المخزنة لسجل العضوية، و`membership_status` حالتها الفعلية للطالب: active/pending/expired/left/removed بحسب السجل وصلاحية الاشتراك. invalid active تُعرض expired إلا إذا الاشتراك pending. يمكن أن تبقى العضوية active في مجموعة closed؛ افحصوا أيضاً `status` و`can_view_members` ولا تستنتجوا حق الوصول من كلمة active وحدها.

زر الأعضاء يظهر حصراً عند `can_view_members=true`، والمسار في `members_endpoint`. بعد انتهاء الاشتراك أو المغادرة أو إغلاق المجموعة تبقى بيانات المجموعة التاريخية الأساسية، لكن قائمة الأعضاء ممنوعة ويكون endpoint=null. استدعاء المجموعة الممنوعة/الأجنبية يعيد 404 لتجنب كشف وجودها.

الأعضاء المعروضون فقط أصحاب عضويات فعالة واشتراكات مادة كاملة سارية مطابقة للمجموعة. بيانات العضو حصراً `member_id, display_name, avatar_url`. `member_id` معرف ملف الطالب، وليس users.id، ولا يمنح حق طلب بياناته. لا هواتف ولا بريد ولا أرقام حسابات خاصة. تعرض القائمة الطالب نفسه أيضاً إذا كان مؤهلاً. لا تستخدموا الأسماء أو الأعداد المخزنة في cache بعد فقد صلاحية عرض الأعضاء.

## 8. حالات فارغة وأخطاء ومعالجتها

| HTTP | المعنى وطريقة التعامل |
|---|---|
| 200 مع data=[] | لا نتائج/لا اختبارات/لا مجموعات/لا محاولات، اعرضوا empty state مع إزالة رسالة تعطل الخدمة |
| 401 | توكن مفقود/غير صالح أو جلسة جهاز غير فعالة؛ طبقوا تجديد التوكن/إعادة الدخول الموجود، ولا تكرروا الطلب بلا حد |
| 403 | دور غير مسموح أو حساب/طالب غير فعال، أو ملكية اشتراك الحجز مرفوضة |
| 404 | مورد غير موجود أو محجوب بالسياسة؛ لا تعرضوا أسماء أو بيانات احتياطية من طالب آخر |
| 405 | Method غير متاح؛ لا تحاولوا CRUD عام |
| 409 عند الحجز | تعارض أو عقد الحجز القديم؛ استخدموا المسار الجديد وأعيدوا تحميل التقويم |
| 422 | قيم query/body غير صالحة، فترة أطول من 31 يوماً، timezone غير صحيح، grade غير مدعوم، إلخ؛ اقرأوا errors إن وجدت |

مثال قائمة فارغة حقيقي، HTTP 200:

```json
{
  "status": true,
  "data": [],
  "meta": {
    "current_page": 1,
    "per_page": 20,
    "total": 0,
    "last_page": 1
  }
}
```

مثال منع قراءة أعضاء مجموعة أجنبية، HTTP 404:

```json
{
  "message": "Not Found"
}
```

مثال grade غير مدعوم، HTTP 422:

```json
{
  "message": "Grade filtering is not supported: teaching grades are not mapped to teacher subjects.",
  "errors": {
    "grade": [
      "Grade filtering is not supported: teaching grades are not mapped to teacher subjects."
    ]
  }
}
```

## 9. ما اختُبر وحدود بيانات التجربة

تم تطبيق 12 ملفاً محدداً على المحلي والسيرفر مع فحص بصمات النسخة السابقة، ونسخة تراجع للكود ونسخة SQL قبل النشر. لا توجد ترحيلات قاعدة بيانات جديدة لهذا الطلب، ولم تُرفع نسخة مشروع كاملة أو vendor أو .env.

- نجحت مجموعة الاختبارات الكاملة على المحلي: **84 اختباراً و1380 تحققاً**؛ منها 14 اختبار تكامل جديد لهذه المتطلبات.
- نجح **38 فحصاً** على تطبيق السيرفر الفعلي وقاعدة MySQL، تشمل القائمة والبحث، رفض CRUD العام، الحجز من التوافر والإلغاء، تمييز المحجوز وغير المؤهل والمغلق، معرف الاختبار المنشور وفتح بياناته، محاولات الطالب والتصحيح المعلق، التاريخ بعد الانتهاء، المجموعة وأعضاؤها ومنع الحساب الآخر.
- HTTPS على عنوان التطبيق: دليل المدرسين 200، الأبرز 200، درس 15 يعيد quizzes[].id، واختباراتي دون مصادقة 401.
- تشمل الاختبارات المحلية أيضاً الدليل الفارغ والأبرز الفارغ، الصفحات والفلاتر، اليوم المحجوز كلياً، الفترات خارج التوافر، Asia/Damascus، تناقض العدد/النشر، الدرجة صفر، مهلة المحاولة، انتهاء/مغادرة المجموعة والتكرار في العدد.
- جميع بيانات فحص السيرفر المؤقتة أُنشئت ضمن transaction ثم تم rollback، بما فيها الطلاب والتوكنات والأجهزة والحجوزات. **أرقام teacher=10/enrollment=42/group=7 وغيرها في أمثلة الفحص المؤقت ليست حسابات أو مواعيد متاحة للاستعمال الآن**. الأمثلة لقطة استجابة فعلية وقت الفحص، ولا يجوز تثبيتها بالواجهة. لم تُنشأ حسابات دائمة أو كلمات مرور جديدة.
- بيانات حقيقية موجودة وقت الفحص للبدء بالقراءة العامة: أحمد الشامي teacher_id=1، ريم الحسن=2، خالد المصري=3، هبة الخطيب=4؛ ودرس التشبيه lesson_id=15/content_id=15/quiz_id=15. الحساب الذي سيختبر الوصول للاختبار يجب أن يملك الاشتراك المطلوب عبر تدفق المشروع الموجود؛ لا يكفي هذا الرقم لإعطاء الصلاحية.
- لإعادة تجربة الحجز/المجموعة بالواجهة: استخدموا حساب QA المصرح لكم به، فعّلوا اشتراك المادة المطابق عبر الإدارة الموجودة، واجعلوا المدرس يحدد توافراً مستقبلياً، وأضيفوا الطالب للمجموعة عبر آلية المشروع. اسحبوا المعرفات الفعلية من الاستجابات. لا تستخدموا أرقام أمثلة الفحص المؤقتة ولا تطلبوا بيانات طلاب حقيقيين للاختبار.
- لم يُختبر Flutter نفسه أو تحميل متزامن واسع أو PostgreSQL في هذا التسليم. اختبارات السيرفر مرّت عبر Laravel HTTP kernel وmiddleware وسياسات الوصول الفعلية مع توكنات أجهزة محفوظة مؤقتاً؛ الطلبات العامة فُحصت أيضاً عبر HTTPS.

## 10. قائمة العمل على Flutter قبل التسليم

1. ربط شاشة الأساتذة بالدليل الجديد مع pagination والبحث على الخادم، وفصل الأبرز.
2. حذف إرسال grade وتوضيح أن region_id فلتر اختياري لمنطقة المدرس؛ عدم فرض منطقة الطالب أو اشتراكه على الدليل.
3. استبدال مصدر شاشة المواعيد بـcalendar، تمييز reasons، وتفعيل زر الحجز فقط من bookable/availability_id/eligible_enrollment_ids.
4. نقل POST الحجز إلى teacher-availabilities، وحفظ session_id من نتيجة 201 لتفاصيل الحجز والإلغاء؛ تحديث البيانات بعد كل عملية.
5. قراءة quiz_id من quizzes[].id، مع fallback محمي وحالة «لا يوجد اختبار منشور»؛ مسح cache الاستجابة القديمة.
6. ربط «اختباراتي» مع scopes وتفاصيل المحاولات، وإظهار pending/صفر/انتهاء الزمن بصورة صحيحة.
7. ربط «مجموعاتي» مع active/history/all، وإظهار الأعضاء فقط عند can_view_members؛ إخفاء cache الأعضاء عند 404 أو انتهاء الصلاحية.
8. عدم تضمين كلمات مرور أو توكنات في logs أو تقارير الفريق؛ الاحتفاظ بتدفق المصادقة والجهاز الموجود.

المنجز منشور الآن. المتبقي خارج هذا الطلب: تنفيذ وربط واجهات Flutter، وأي تصميم جديد يربط صفوف التدريس بالمواد قبل إضافة grade. لا يتضمن هذا التسليم AI أو بوابات دفع أو نظام تقييم نجوم.
