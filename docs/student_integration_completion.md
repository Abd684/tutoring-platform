# استكمال ربط واجهات الطالب — 2026-10-15

جميع المسارات تبدأ بـ `/api/v1`. أرسل `Accept: application/json`، و`Authorization: Bearer <access_token>` لمسارات الطالب والمدرّس المحمية. الحساب والملف الطلابي والجهاز والجلسة يجب أن تكون فعالة. توكنات الطلاب القديمة غير المرتبطة بجلسة جهاز تحتاج إعادة تسجيل الدخول.

## 1. البروفايل

`PUT /profile` أو `PATCH /profile` يعدّل الحساب المصادق عليه فقط. لا تستخدم `/auth/register` للتعديل.

```json
{"name":"اسم الطالب","phone":"0990000000","email":"student@example.com","region_id":1,"school_id":2,"grade":"12"}
```

جميع الحقول اختيارية في التعديل، وعند إرسالها يجب ألا تكون فارغة. `name` و`email`: حد 255، `phone`: حد 30، `grade`: نص حد 100. البريد فريد باستثناء المستخدم الحالي. المدرسة يجب أن تتبع المنطقة الجديدة أو المنطقة المحفوظة إذا لم تُرسل. تغيير المنطقة مع مدرسة قديمة لا تتبعها يعطي `422`. الحقول الإدارية لا تعدَّل من هذا المسار.

استجابة `200` بنفس عقد `GET /me`:

```json
{"status":true,"user":{"id":11,"name":"اسم الطالب","phone":"0990000000","email":"student@example.com","role":"student","status":"active","region_id":1,"avatar_url":null},"student":{"id":7,"grade":"12","school_id":2,"status":"active","school":{"id":2,"region_id":1}}}
```

المدرسة الفعلية تشمل حقولها وعلاقة المنطقة. القيم هنا توضيحية.

## 2. الصورة

`POST /profile/avatar` بصيغة multipart وحقل `avatar`: JPEG/PNG/WebP حتى 5 MB. يعيد `{"status":true,"data":{"avatar_url":"https://.../storage/avatars/..."}}`.

`DELETE /profile/avatar` يعيد نفس العقد مع `avatar_url: null`. الاستبدال والحذف يزيلان الملف السابق. `/me` وتسجيل الدخول يرجعان `user.avatar_url`. الصور عامة؛ ملفات الدروس خاصة.

## 3. المحتوى والمرفقات

`GET /lessons/{lesson}/contents` يرجع المحتويات المنشورة مع `title`, `description`, `learning_objectives` كمصفوفة نصوص أو null، `duration_seconds` كعدد أو null، `price`, `assets_count`, `quizzes_count`.

`POST /teacher/contents` و`PATCH /teacher/contents/{content}` يقبلان الوصف والأهداف والسعر؛ التعديل يتطلب ملكية المدرّس للمحتوى. رفع الملف عبر `POST /teacher/contents/{content}/asset` بحقل `file`. يمكن إرفاق PDF بمحتوى فيديو. مدة الفيديو تُقرأ فعلياً باستخدام ffprobe من الملف المؤقت عند الرفع (بما فيه الرفع إلى S3)، ولا توضع قيمة افتراضية عند تعذّر قراءتها. لإعادة قراءة مدد الملفات القديمة شغّل `php artisan media:probe-durations`. أمر إعادة القراءة يجلب الملفات البعيدة مؤقتاً للمعالجة ثم يزيل النسخة المؤقتة؛ قد يستغرق وقتاً مع ملفات كبيرة.

```http
GET /contents/123/assets
POST /content-assets/456/access-token
POST /contents/123/playback-token
```

قائمة المرفقات تتطلب اشتراكاً صالحاً، وتعيد `id`, `mime_type`, `file_size`, `duration_seconds`, `token_endpoint` دون مفتاح التخزين. `access-token` يفتح الملف المحدد؛ `playback-token` يختار أحدث فيديو فعال عندما يكون المحتوى فيديو، فلا يختار PDF المرفق بالخطأ.

```json
{"status":true,"message":"Playback token created successfully.","data":{"playback_url":"https://.../content-assets/456/play?student=7&expires=...&signature=...","expires_at":"2026-10-15T15:00:00+00:00"}}
```

الرابط صالح لخمس دقائق، ويتطلب Bearer token أيضاً. استعمل مشغلاً أو عارض PDF يدعم إرسال الترويسة. عند الفتح يُفحص الطالب وملكية الرابط والاشتراك من جديد، وتُمنع الاستجابة من التخزين في cache. تدعم الملفات المحلية وS3 طلبات Range والتنقل داخل الفيديو دون إتاحة رابط تخزين عام. لا تضع الملفات على `public` أو في document root؛ النسخة الحالية ترفض إصدار رابط لها على قرص `public`. نقل ملفات عامة قديمة إلى تخزين خاص مسؤولية النشر ولا يتم حذفها آلياً.

## 4. الاشتراكات

التغطية: `teacher_subject` لكل المحتويات التابعة، `unit` للوحدة فقط، `content` للمحتوى المحدد. يلزم `active`، وبداية لم تأتِ بعد تمنع الوصول، والانتهاء عند الوقت الحالي أو قبله يمنعه. null في البداية/الانتهاء يعني عدم وجود حد من تلك الجهة. يلزم أيضاً نشر المحتوى والدرس والوحدة وفعالية المادة والمدرّس. الرفض يعود `404`؛ الرابط غير الصحيح أو المنتهي يعود `403`، والتوكن الملغى `401`.

## 5. الإنجاز والتقدم

```http
POST /student/contents/{content_id}/complete
GET /student/teacher-subjects/{teacher_subject_id}/progress
```

الإكمال بلا body، ويتطلب الوصول إلى المحتوى المنشور باشتراك صالح. التكرار لا يكرر الإنجاز ولا يغيّر وقت الإنجاز الأول. يعود نفس عقد التقدم:

```json
{"status":true,"data":{"teacher_subject_id":4,"total_contents":8,"completed_contents":2,"completed_content_ids":[17,18],"progress_percentage":25}}
```

المقام هو **كل المحتويات المنشورة في الدروس والوحدات المنشورة للمادة**، حتى لو كان اشتراك الطالب بوحدة واحدة فقط. لا تُحسب المسودات والأرشيف. الإنجاز إقرار من الطالب عبر الإجراء، وليس إثبات مشاهدة الفيديو كاملاً. قراءة التقدم تتطلب اشتراكاً صالحاً في المادة أو جزء منها؛ البيانات المحفوظة لا تُحذف عند انتهاء الاشتراك.

## 6. المدرّس والمادة

`GET /teachers/{teacher}` عام، ويعيد `id`, `name`, `avatar_url`, `bio`, `specialization`, `experience_years`, `students_count`, `completion_rate`.

`experience_years` = null حتى يحدّثها المدرّس عبر `PATCH /teacher/profile`، عدد صحيح 0–100 أو null. لا يوجد نظام تقييم نجوم.

`students_count`: عدد الطلاب المميزين في اشتراكات المدرّس بحالتي active وexpired، عبر مستويات الاشتراك الثلاثة، دون تكرار الطالب. `completion_rate`: عدد إنجازات الطلاب المشتركين بالمادة كاملة مقسوماً على عدد أزواج الطالب/المحتوى المنشور في مواد المدرّس الفعالة، كنسبة 0–100، أو null عند عدم وجود مقام. اشتراكات الوحدة والمحتوى لا تدخل مقام هذا المعدل. الاشتراكات المكررة للطالب بالمادة تُحسب مرة واحدة.

`GET /student/teacher-subjects/{id}` للمصادق عليه يعيد السعر، المادة، `units_count`, `lessons_count`, `contents_count`, `progress`، وشجرة الوحدات والدروس والمحتويات المنشورة. كل محتوى يتضمن الوصف والأهداف والمدة و`has_access`، دون روابط ملفات خاصة. بقية مسارات التصفح القديمة باقية.

## 7. الجلسات

مسارات المواعيد والحجز والإلغاء القديمة باقية. `GET /student/bookings` يعيد القادمة افتراضياً. استعمل `?scope=history` للسابقة أو المكتملة والملغاة، و`?scope=all` للجميع. `GET /student/sessions/{session}` يعرض حالة جلسة تخص الطالب فقط.

`POST /teacher/sessions/{session}/complete` يؤكد الإنهاء بعد `ends_at`؛ تكراره آمن، والملغاة لا تُنهى. `PATCH /teacher/sessions/{session}` مع `status: completed` يبقى مدعوماً مع فحص وقت النهاية. انتهاء الوقت وحده لا يغيّر الحالة. تسجيل الحضور منفصل عن الإنهاء.

يمكن إنشاء جلسة فردية دون `enrollment_id` ليحجزها الطالب لاحقاً؛ الجلسة الجماعية تحتاج `group_id`. المسار الصحيح لإلغاء الجلسة من المدرّس `POST /teacher/sessions/{session}/cancel`، مع إبقاء الاسم القديم ذي `/v1/` الإضافية للتوافق.

## 8. نقل الجهاز

1. من الجهاز الجديد: `POST /auth/device/transfer-requests` أو المسار السابق `POST /auth/device/transfer` بنفس body تسجيل الدخول: email/password/device_uuid/platform وبيانات الجهاز الاختيارية. أصبح المسار السابق **طلباً مؤجلاً ولا يرجع توكن دخول فوراً**.

```json
{"status":true,"data":{"id":12,"status":"pending","expires_at":"<after 72 hours>","transfer_token":"<secret returned once>"}}
```

الاستجابة `202`. لا تُلغى جلسة الجهاز القديم أثناء الانتظار. طلب ثانٍ أثناء وجود طلب معلق يعطي `409`. احتفظ بالرمز سرياً؛ المخزّن في قاعدة البيانات hash فقط.

2. الجهاز القديم يجلب `GET /student/device-transfer-requests`، أو `GET /student/notifications` لإظهار إشعار داخل التطبيق. سجل الإشعار يحتوي نوع `device_transfer_requested`، وbody نص JSON يتضمن id الطلب ووصف الجهاز الجديد والمهلة. يجب أن تجلب الواجهة الإشعارات دورياً أو عند فتح التطبيق. **لا توجد خدمة FCM/APNs مهيأة في هذا المشروع؛ هذه إشعارات محفوظة داخل التطبيق، وليست push عند إغلاقه.**

3. على الجهاز القديم بتوكن جلسته فقط: `POST /student/device-transfer-requests/{id}/approve` أو `/reject`. القبول ينقل فوراً، والرفض يبقي القديم فعالاً. بعد المهلة تكون الأولوية للنقل التلقائي، فلا يقبل رفض متأخر.

4. الجهاز الجديد يستعلم `GET /auth/device/transfer-requests/{id}` بترويسة `X-Transfer-Token: <secret>`؛ لا تضع الرمز في query string. الحالات: pending/approved/auto_approved/rejected/cancelled. لا تعاد توكنات الدخول في الاستعلام.

5. بعد الموافقة: `POST /auth/device/transfer-requests/{id}/claim` بنفس الترويسة يعيد عقد تسجيل الدخول القديم مع access_token وrefresh_token. استلام مرة واحدة؛ نافذته 72 ساعة بعد التنفيذ. بعد ذلك يمكن تسجيل الدخول المعتاد من الجهاز الجديد. لا يسمح بالاستلام المبكر أو بعد الرفض.

النقل يلغي كل access tokens والجلسات والـrefresh tokens القديمة، ويفعّل الربط الجديد. يسمح بالعودة لاحقاً لجهاز سابق عبر دورة موافقة جديدة. الحساب الموقوف أو الجهاز الجديد المحظور يلغي الطلب دون تعطيل الجهاز القديم. عدة طلاب يمكنهم استخدام نفس الجهاز، وكل طالب له ربط جهاز فعال واحد.

المجدول `devices:resolve-transfers` يعمل كل دقيقة؛ لذلك التنفيذ التلقائي يحصل في أول دورة بعد 72 ساعة. الاستعلام والاستلام يحلان الطلب المنتهي أيضاً. يجب تشغيل Laravel scheduler على السيرفر:

```cron
* * * * * cd /path/to/liqaa_app && php artisan schedule:run >> /dev/null 2>&1
```

## 9. الصلاحيات

لا تُفعّل apiResources العامة المعطلة. الدفع يتطلب مدير الشركة، وإدارة المحتوى والجلسات تتطلب المدرّس المالك، وكل عمليات الطالب تستنتج هويته من التوكن. Middleware الطالب يفحص فعالية الحساب والملف والجهاز والجلسة؛ لا تعتمد على device_uuid وحده لإجازة قرار النقل. مصادقة الطلاب عبر Bearer token المرتبط بجلسة الجهاز.

التخزين المسجّل يدوياً يجب أن يكون قرصاً خاصاً معروفاً ومفتاحه داخل `teachers/{teacher_id}/contents/{content_id}/`. لا يمكن تسجيل ملف يخص مدرساً آخر.

## 10. الاشتراك التجريبي والنشر

تفعيل حقيقي عبر نظام الاشتراكات المعتاد، بلا تجاوز للصلاحيات أو تسجيل دفعة وهمية:

```sh
php artisan student:grant-trial 11 4 --days=14
```

المعامل الأول **user_id** أو البريد، وليس student_id. يتحقق الأمر من فعالية الطالب والمادة والمدرّس. إذا كان هناك اشتراك مادة فعال لم ينتهِ، يحتفظ به بدلاً من استبداله أو تكراره.

محلياً فقط يمكن تشغيل `php artisan student:prepare-demo` لإعداد حسابات MobileMediaTestSeeder وفيديو اصطناعي قصير وملفات PDF وموعـد متاح. يمنع الأمر في production؛ لا تشغله على السيرفر الحقيقي.

النشر: ارفع الكود دون `.env` أو ملفات المستخدمين، احتفظ بنسخة احتياطية من الكود وقاعدة البيانات، ثم `php artisan migrate --force` و`php artisan optimize:clear` و`php artisan storage:link`. فعّل scheduler وثبّت ffprobe إن أردت استخراج المدد. راجع `APP_URL` وعنوان public storage وفق رابط نشر التطبيق الفعلي. حافظ على التوكنات وجلسات الجهاز الموجودة الصالحة؛ لا تُلغها جماعياً عند النشر.
