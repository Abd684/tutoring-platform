# اللقاء — ربط قواعد العمل الحرجة

المرجع: التوصيف المرفق، صفحة 18، وقاموس البيانات للصفحات 11–13. تاريخ التحديث: 2026-10-17.

## ما تغيّر

1. الاشتراك يخزن أحد الأنواع `teacher_subject` أو `unit` أو `content` فقط. يقبل الخادم أسماء الأصناف القديمة لهذه الأنواع الثلاثة للتوافق ويحوّلها إلى القيم الموحّدة.
2. الجلسة الجماعية مرتبطة بمجموعة، و`enrollment_id = null`. الفردية مرتبطة باشتراك، و`group_id = null` وسعتها 1. التعديل يُفحص على الحالة النهائية كاملة، وليس الحقول المرسلة وحدها.
3. المحتوى المنشور يُفتح بحسب نطاق اشتراك فعّال بدأ ولم ينته، مع فحص حالات الطالب والمدرّس والمادة والآباء المنشورين. شراء المادة يفتح وحداتها ومحتواها، وشراء الوحدة يفتح محتواها فقط. فتح المحتوى لا يسجل حضوراً ولا إنجازاً تلقائياً.
4. جهاز فعّال واحد لكل طالب، مع السماح باستعمال هاتف واحد لعدة طلاب. `revoked` يعني إلغاء ارتباط قابل لإعادة الربط، و`blocked` يعني حظر الجهاز. اكتمال النقل يبطل الارتباط والجلسات والتوكنات القديمة فوراً.
5. الخادم هو صاحب قرار السماح؛ تسجيل الدخول والدور والجهاز في Middleware، وملكية الموارد والوصول في Policies، وقواعد التوافر والسعة والتعارض في الخدمات.

## الإعدادات المشتركة

عنوان API:

```text
https://mandobe.net/liqaa/api/v1
```

للطلبات المحمية أرسل `Authorization: Bearer <access_token>` و`Accept: application/json`. توكن الطالب يجب أن يصدر من دخول الطالب أو استلام نقل الجهاز؛ التوكن العام غير المرتبط بجلسة جهاز لا يكفي.

## الحجز من التوافر — يلزم تحديث تطبيق الهاتف

لا تنشئ جلسة فارغة لعرضها كوقت متاح. المدرّس يحفظ التوافر عبر المسارات الموجودة تحت `/teacher/availabilities`، والجلسة الفعلية تنشأ وقت حجز الطالب.

### عرض الفترات المتاحة

```http
GET /teachers/{teacher}/available-slots?from=2026-10-20T00:00:00Z&to=2026-10-27T00:00:00Z
```

الفترة الافتراضية 7 أيام، والحد الأقصى 31 يوماً. أرسل التوقيت بصيغة ISO 8601 مع منطقة زمنية، ويفضل UTC. الخادم يراعي المنطقة الزمنية للتوافر ويطرح أوقات الجلسات غير الملغاة وتعارضات الطالب.

شكل الرد:

```json
{
  "status": true,
  "data": [
    {
      "availability_id": 15,
      "starts_at": "2026-10-20T10:00:00+00:00",
      "ends_at": "2026-10-20T12:00:00+00:00",
      "eligible_enrollment_ids": [27]
    }
  ]
}
```

`data` قائمة فترات، وليست جلسات جاهزة، وليست استجابة pagination. يمكن حجز جزء من فترة التوافر، والخادم يعيد التحقق وقت الحجز حتى لو كانت القائمة المعروضة قديمة.

### إنشاء الحجز

```http
POST /teacher-availabilities/{availability_id}/book
```

```json
{
  "enrollment_id": 27,
  "starts_at": "2026-10-20T10:00:00Z",
  "ends_at": "2026-10-20T11:00:00Z"
}
```

نجاح `201`: `data` يحتوي الجلسة الجديدة و`id` و`type = INDIVIDUAL` و`capacity = 1` و`enrollment_id` و`availability_id` و`status = scheduled`. لا ترسل `teacher_id` أو `student_id` لتحديد صاحب العملية.

بعد حجز 10–11 من توافر 10–12، تبقى 11–12 قابلة للحجز. تكرار الحجز أو تعارضه مع جلسة أخرى للمدرّس أو الطالب يرجع `409`.

**المسار القديم** `POST /sessions/{id}/book` يرجع `409` مع توجيه إلى المسار الجديد. لا تعتمد على مسار الجلسات القديم لجلب أوقات الحجز؛ استخدم `available-slots` أعلاه.

### إلغاء الحجز

```http
DELETE /sessions/{session_id}/booking
```

الإلغاء مسموح لصاحب الحجز الفردي قبل بدايته. تصبح `status = cancelled`، ويبقى `enrollment_id` محفوظاً، وتتحرر الفترة في حساب التوافر. إعادة إلغاء الحجز نفسه لا تنشئ سجلاً جديداً. لا تفترض أن الإلغاء يرجع الجلسة إلى `scheduled` أو يمسح الاشتراك.

## جلسات المدرّس والمجموعات

المسارات الموجودة لإنشاء/تعديل الجلسات تحت `/teacher/sessions` مستمرة. مثال التحويل من جماعية إلى فردية:

```json
{
  "type": "INDIVIDUAL",
  "group_id": null,
  "enrollment_id": 27
}
```

التحويل المعاكس يتطلب `type = GROUP` و`group_id` وإرسال `enrollment_id = null`. كل الموارد يجب أن يملكها المدرّس. لا يمكن جدولة جلسة جماعية تتجاوز صلاحية اشتراك أحد أعضائها الفعّالين.

إضافة طالب للمجموعة عبر `POST /teacher/groups/{group}/enrollments` تتطلب اشتراك مادة كاملة، لنفس المادة والمدرّس، وفعّالاً خلال الجلسات المجدولة. شراء وحدة أو محتوى وحده لا يسمح بالانضمام.

## شراء المحتوى والوصول

طلب شراء مادة معلّق لا يمنح الوصول، ولا يمنع طلب شراء وحدة منها؛ لكنه يمنع تكرار طلب شراء المادة نفسها. الاشتراك الفعّال الذي يغطي المنتج يمنع شراء المنتج المغطى مرة ثانية. الخادم يتحقق من النطاق في الفيديو وPDF وروابط التشغيل وبيانات الاختبارات ومحاولاتها وأجوبتها وإكمال المحتوى.

المسارات الحالية للتشغيل والاختبارات والإنجاز مستمرة. تعامل مع `404` على مورد محتوى محمي كعدم توافر/عدم سماح، وليس كدليل على أن رقم المورد غير موجود.

## نقل الجهاز

آلية الموافقة الموجودة مستمرة:

- إنشاء الطلب: `POST /auth/device/transfer-requests`، مع `email`, `password`, `device_uuid`, `platform`؛ الرد `202` يتضمن `id`, `transfer_token`, `expires_at`.
- متابعة الحالة: `GET /auth/device/transfer-requests/{id}`، مع هيدر `X-Transfer-Token`.
- الجهاز الحالي: `GET /student/device-transfer-requests`، ثم `POST /student/device-transfer-requests/{id}/approve` أو `/reject`، بتوكن الجهاز الحالي المرتبط بالطالب نفسه.
- الجهاز الجديد بعد الموافقة: `POST /auth/device/transfer-requests/{id}/claim`، مع `X-Transfer-Token`؛ يصدر جلسة الدخول الجديدة، ويمكن الاستلام مرة واحدة.

إذا انتهت 72 ساعة والطلب ما زال معلّقاً، يُحلّ تلقائياً عند فحصه أو تشغيل مهمة المعالجة. لا تغيّر الجهاز الفعّال في الهاتف قبل اكتمال النقل واستلام التوكن الجديد. الهاتف القديم الذي صار `revoked` يستطيع العودة عبر النقل؛ الجهاز `blocked` يبقى مرفوضاً.

## أخطاء يجب التعامل معها

| الرمز | المعنى المعتاد |
|---|---|
| 401 | توكن مفقود/ملغى أو جلسة جهاز غير صالحة |
| 403 | الدور أو الحساب أو ملكية الاشتراك للدفع/موافقة النقل لا تسمح |
| 404 | المورد غير متاح لهذا الحساب، أو لا يملك الطالب الحجز/حق المحتوى |
| 409 | تعارض حجز/سعة/حالة أو طلب مكرر أو استخدام مسار الحجز القديم |
| 422 | بيانات الجلسة النهائية متناقضة، نطاق اشتراك خاطئ، أو فترة غير صالحة |

لا تعتمد على نص الرسالة وحده؛ افحص HTTP والحقول المرجعة. أخطاء التحقق ترجع `errors` وقد تختلف بنية أخطاء الأعمال عن أخطاء Policies.

## التحقق

- الاختبارات المحلية على SQLite داخل الذاكرة: **70 اختباراً و1237 تحققاً**.
- الترحيلات مطبقة على MySQL المحلي بعد نسخة SQL احتياطية.
- فحص تطبيق السيرفر على MySQL: **29 حالة** داخل معاملة أُرجعت بالكامل، ومنها الحجز والإلغاء والوصول ونقل الجهاز والقيد الفريد.
- اختبار ضغط لطلبات متزامنة من عدة عمليات واختبار PostgreSQL لم يُنفّذا؛ الأقفال والقيد الفريد موجودان، لكن لا يُعدّ ذلك قياساً عملياً للتزامن العالي.
